RE315 port investigation
========================

Purpose
-------
Develop OpenWrt support for a TP-Link RE315 used as an Ethernet-fed access
point. The intended physical result is Ethernet from the existing gateway
to the RE315, with clients using its 2.4 GHz and 5 GHz access points.

This record contains source and vendor-firmware analysis. No RE315 device
was connected to the analysis environment. It is not a flash procedure,
a tested device definition, or a declaration of hardware support.

Payload extraction
------------------
Two bounded ranges were copied with dd and decompressed with xz in
LZMA mode. No payload code was executed.

Range A:
  update offset: 0x000000D4
  sliced length: 49050 bytes
  decompressed length: 132124 bytes
  decompressed SHA-256:
  a68bfdf536b3963861570c98782ecbc379882864003f44f1e778bcc01373659c

Range B:
  update offset: 0x0000C070
  sliced length: 1499294 bytes
  decompressed length: 5077312 bytes
  decompressed SHA-256:
  800aa83243b36ff59c0fabd062df271932ab934deed50f89b3e66863b526f0aa

Range B contains the main MIPS VxWorks image, including the strings:
  VxWorks5.5.1
  Sep  4 2020
  MT7628(MIPS32)

This establishes a VxWorks main-system payload in this vendor release.
It does not identify the currently installed firmware.

Range A contains U-Boot 2014.04-rc1 / leopard_e material identifying an
ARM platform. It must not be treated as the MT7628 MIPS main bootloader.
The precise role of that separate payload has not been established.

A MINIFS marker was observed at update-file offset 0x0017B014.
This is a file-container observation, not a physical flash partition.

Configured memory boundary
--------------------------
Range B includes a VxWorks symbol table. For sysMemTop:

  symbol-name offset in decompressed file: 0x0046A5FC
  symbol-name pointer: 0x8046B5FC
  symbol-table entry offset: 0x004D2030
  symbol value: 0x800FE4EC
  inferred image address base: 0x80001000
  function file offset: 0x000FD4EC

The symbol-table entry consists of these little-endian words:
  00000000 8046b5fc 800fe4ec 00050000

The function's first 14 instruction words are:
  3c04804f 8c825568 14400008 3c03804f
  8c62556c 14400004 00000000 3c028100
  ac62556c 8c62556c ac825568 3c02804f
  03e00008 8c425568

At file offset 0x000FD508, instruction 0x3C028100 is
lui v0,0x8100. In the zero-initialized path this supplies 0x81000000
to the memory-top globals. Relative to MIPS cached segment base
0x80000000, that is a 0x01000000-byte (16 MiB) boundary.

Conclusion: this vendor image has a default 16 MiB memory boundary.
This is strong static evidence for its memory configuration, not a
measurement of physical or usable RAM on the user's unit. The function
can use already initialized globals, so runtime override has not been
excluded. Do not publish 64 MiB as an established RE315 specification.

Vendor flash-layout data
------------------------
Range B contains the flashLayout symbol, value 0x804736A4, corresponding
to file offset 0x004726A4. After 12 zero metadata bytes, six 24-byte
entries contain an initially zero offset, a size, and a 16-byte name.

Entry       Size hexadecimal    Size bytes
BOOTIMG     0x0000D000           53248
FIRMWARE    0x003ED000           4116480
CONFIG      0x00002000           8192
EXPLOG      0x00002000           8192
PROFILE     0x00001000           4096
RADIO       0x00001000           4096
TOTAL       0x00400000           4194304

These are observed vendor-declared sizes. Their total independently
matches the 4 MiB flash chip in the FCC sample.

The flashIoInit symbol has value 0x8008AF58, hence file offset 0x00089F58.
Its initialization loop at file offset 0x0008A018 is:
  3c028047 244336b0 3c028047 24453740
  00002021 8c620004 ac640000 24630018
  1465fffc 00822021

The loop sets the record pointer to 0x804736B0, the end pointer to
0x80473740, and the running offset to zero. It loads each size at
record+4, stores the running offset at record+0, advances by 0x18,
and adds the size in the branch delay slot. This establishes these
computed starts for the vendor program:

Entry       Start       Size        End, exclusive
BOOTIMG     0x000000    0x00D000    0x00D000
FIRMWARE    0x00D000    0x3ED000    0x3FA000
CONFIG      0x3FA000    0x002000    0x3FC000
EXPLOG      0x3FC000    0x002000    0x3FE000
PROFILE     0x3FE000    0x001000    0x3FF000
RADIO       0x3FF000    0x001000    0x400000

This is the downloaded program's computed flash map. It has not been
matched to a readout of the user's device. Erase geometry, calibration
contents, later modifications and applicability to the installed
firmware remain unverified. The RADIO name alone does not identify the
complete per-radio NVMEM layout. Do not turn these offsets into flashing
commands or assume that the C50 v6 EEPROM length fits this region.

The image also contains implementation/help text for flash layout,
flash reads and memory inspection. Presence in the binary does not prove
that the user's firmware exposes an accessible console.

The update container has an IMG0 marker at file offset 0x14 and a size
word matching the update length minus 0x14. Upgrade-rejection strings
refer to magic, product/main-version/OEM IDs, MD5 checks and section
sizes. The complete checksum/signature convention and accepted repacking
procedure remain unknown; no replacement container has been produced.

Physical evidence still required
-------------------------------
1. Actual device label: full model/region, hardware revision and FCC ID.
2. Installed firmware version and complete build string.
3. Read-only serial boot log and verified console electrical/pin data.
4. Bootloader memory report, commands and any supported RAM boot path.
5. Complete flash backup from this unit, with repeated-read integrity
   checks and protected bootloader/factory regions identified.
6. Per-interface MAC and radio calibration locations.
7. Verified Ethernet port, reset, button and LED assignments.

A configuration export is not a full flash backup. A factory reset is
not proof of recovery from a failed firmware image. A downloadable
vendor update is not the user's factory-data backup.
